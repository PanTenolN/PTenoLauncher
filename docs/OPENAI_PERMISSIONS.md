# Підключення власного OpenAI API-ключа

Перевірено за офіційною документацією 2026-10-30:

- https://developers.openai.com/api/docs/guides/rbac
- https://help.openai.com/en/articles/8867743-assign-api-key-permissions

У «Налаштування → Підключення ШІ» вставте власний ключ і збережіть його. Збереження не надсилає запитів. Ключ прихований у полі, зберігається через наявний захищений vault; перегляд збереженого стану не розшифровує його. API оплачується окремо від підписки ChatGPT; актуальні умови перевіряйте у своєму OpenAI-проєкті. Ключ розробника не вбудований.

Надавайте лише доступ, потрібний для створення відповідей через Responses і використання вибраної моделі. Обмеження ключа та роль його власника в проєкті перевіряються окремо. Дозволи Files, Assistants, Threads, адміністрування та All для цього workflow не потрібні. Модель повинна підтримувати текстові Responses; для перекладів потрібний відповідний structured-output контракт. Каталог сам по собі цього не підтверджує.

Читання `/v1/models` — окремий **необов’язковий** дозвіл. «Перевірити підключення» після окремої згоди робить лише запит каталогу. HTTP 403 тут означає недоступність каталогу, а не доказ неправильного ключа. Введіть дозволений ID моделі в «Додатково» і збережіть модель. Лаунчер не вимагає відкривати всі дозволи.

Успішне читання каталогу позначається як «Каталог доступний; генерацію ще не перевірено». Лише успішний явний Responses-запит для вибраної моделі дає стан отриманої відповіді. Він може оплачуватися. Зміна ключа або моделі скидає це підтвердження. Автоматичного платного тесту немає.

На цьому етапі перевірені локальні HTTP-fixtures (зокрема catalog 403 + Responses success), без реального ключа та платних live-запитів. Реальна доступність моделі, права вашого проєкту, білінг і якість відповідей потребують окремої добровільної перевірки власником ключа.
