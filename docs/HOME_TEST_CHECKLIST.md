# PTenoLauncher — домашня перевірка 0.2.0 Development Preview

Цей чекліст містить ручні перевірки, які ще не підтверджено на реальному ліцензійному акаунті та звичайному Windows-середовищі. Статус кожного пункту спочатку NOT RUN. Успіх автоматичних тестів не є результатом цих перевірок.

## 1. Почни з Portable

1. Розпакуй PTenoLauncher-Portable-0.2.0-win-x64.zip у нову порожню папку. Запускай PTenoLauncher.exe разом з усіма файлами з архіву.
2. Програма використовуватиме власну папку portable-data поруч із EXE. Не копіюй туди свої основні світи або існуючі акаунти.
3. Перевір відкриття вікна. У Налаштуваннях перемкни тему, мову й AI. Теми повинні застосовуватися одразу; основні функції мають працювати з вимкненим AI.
4. Створи окремий профіль PTeno-Test-Vanilla: Minecraft 1.21.1, Vanilla. Переконайся, що вкладка Моди прихована. Вона має з’являтися для Fabric-профілю.
5. Відкрий редактор профілю, увімкни Snapshots і натисни Оновити каталог за наявності інтернету. Запиши, які latest release/snapshot показує каталог. Це перевірка списку, а не доказ запуску всіх snapshot-версій.

Очікування: відкриття без установленого окремо .NET; налаштування збережені після перезапуску; Vanilla не показує Моди.

## 2. Що потрібно для офіційного входу

Для поточного повторного тесту використай окрему папку artifacts/0.2.0/auth-fix-win-x64. Натисни «Виконати вхід» у правій верхній частині вікна — шукати вхід у Налаштуваннях не потрібно. Зареєстрований ID PTenoLauncher уже є стандартним; раніше збережений власний override підтримується. Нижче збережено інструкції для власника застосунку, якщо потрібно налаштувати інший Client ID. Деталі виправлення: docs/AUTHENTICATION_FIX.md.

Потрібні твій особистий Microsoft-акаунт із правом на Minecraft Java Edition та власний дозволений Application (client) ID PTenoLauncher. Шкільний акаунт сам по собі не підтверджує придбану гру.

Якщо власної реєстрації ще немає, спочатку виконай MICROSOFT_AUTH_SETUP.md у корені пакунка. Для системного браузера MSAL використовується redirect URI http://localhost, тип public desktop client; client secret не потрібен. Офіційна інструкція Microsoft: https://learn.microsoft.com/en-us/entra/msal/dotnet/acquiring-tokens/using-web-browsers .

Реєстрація Entra не гарантує доступу до Xbox/Minecraft Services. Якщо власного ID немає або сервіс відхиляє застосунок, познач вхід BLOCKED і передай текст помилки. Інші незалежні перевірки можна продовжити. Не використовуй ID іншого лаунчера.

У Налаштування → Акаунт Microsoft збережи власний Client ID і натисни Увійти через Microsoft. Пароль і MFA вводяться тільки на офіційній сторінці Microsoft у браузері. Перевір нікнейм, UUID і відображення скіна. Запиши, на якому кроці з’явилася помилка, якщо вхід не завершився.

Пароль, MFA-коди, access/refresh tokens і файли secrets/*.dpapi нікому не надсилай. Для звіту достатньо повідомлення програми або скріншота без секретів.

## 3. Vanilla: реальний онлайн-запуск

Лише після успішного підтвердженого входу:

1. На Головній вибери PTeno-Test-Vanilla і Встановити / відновити.
2. Натисни Підібрати й установити Java. Для цього тесту очікується Java 21 x64.
3. Натисни Підготувати до офлайн-гри. Запиши повний статус. За помилки не позначай готовність успішною.
4. У звичайному онлайн-режимі натисни Грати. Перевір, чи з’явилося реальне головне меню Minecraft, а не лише процес Java.
5. Створи новий тестовий світ PTeno-Test-World, зайди в нього, зроби просту зміну й штатно збережи/вийди. Не використовуй важливі світи.
6. Переглянь Налаштування → Консоль гри та статус завершення. Запиши exit code і симптоми, якщо вікно не відкрилося або гра впала.

## 4. Дозволений офлайн-запуск

1. Штатно закрий гру та лаунчер після успішного онлайн-тесту. Не виходь з підтвердженого акаунта.
2. Тимчасово від’єднай ноутбук від інтернету звичайним способом. Запусти Portable, увімкни Офлайн-режим і перевір той самий профіль.
3. Лише якщо лаунчер підтверджує готовність, запусти гру, відкрий PTeno-Test-World і перевір збережену зміну. Штатно вийди.
4. Поверни інтернет після тесту. Якщо запуск заблоковано станом акаунта/файлів, запиши причину; не обходь перевірку й не створюй неавторизовану ідентичність.

Очікування: локальні профілі й налаштування доступні без мережі; дозволений запуск використовує попередньо підтверджений акаунт. Цей сценарій ще не перевірено розробкою.

## 5. Fabric, моди й необов’язкові компоненти

1. Створи другий окремий профіль PTeno-Test-Fabric: Minecraft 1.21.1, Fabric.
2. На Головній завантаж Версії Fabric, вибери сумісну версію, натисни Встановити / відновити та підготуй Java.
3. У Моди знайди Reese's Sodium Options через Modrinth, вибери версію для 1.21.1 / Fabric і додай до кошика. Sodium має додатися як обов’язкова залежність.
4. Якщо метадані пропонують Необов’язкові компоненти, спочатку вони не позначені. Вибери потрібний прапорець: підтвердження встановлення має скинутися. Натисни Застосувати вибір, перевір новий список, причини й розмір. За конфлікту кошик має блокуватися, а вибір можна зняти. Не кожен мод має необов’язкові залежності — відсутній список сам по собі не є помилкою.
5. Підтвердь повний кошик і встанови його. Для невідомого локального JAR потрібне окреме підтвердження внутрішнього попередження. Завантажуватися мають лише потрібні файли; імпортований локальний кореневий JAR повторно з інтернету не потрібен.
6. За підтвердженої готовності й акаунта перевір реальний запуск Fabric та наявність очікуваних модів у грі. Запиши точні версії. Установлення JAR саме по собі не підтверджує роботу модів у Minecraft.

Кнопка Перейти до теки у Моди має відкрити Провідник саме в папці mods вибраного профілю. Перемкни профіль і повтори перевірку: повинна відкритися його власна папка.

Якщо маєш власний легально отриманий JAR, окремо перевір множинний вибір і перетягування у Моди. Залежності визначаються з метаданих і точного SHA512; для невідомих файлів назви проєктів не вгадуються.

## 6. Microsoft: повторний вхід і вихід

Після основних тестів перевір повторне відкриття лаунчера та онлайн-запуск з тим самим акаунтом. Перевір другий власний ліцензійний акаунт лише якщо він є — створювати чи купувати його спеціально не потрібно. Перемикання має вибирати правильний Minecraft UUID. Наприкінці тесту Вийти з акаунта має прибрати саме вибраний акаунт; без збереженого підтвердженого акаунта новий запуск не повинен ставати готовим.

Одне повторне відкриття не доводить повне оновлення прострочених токенів. Для refresh-тесту потрібен окремий повтор після спливу строку; спочатку залиш його NOT RUN.

## 7. Setup — окрема перевірка

PTenoLauncher-Setup-0.2.0-win-x64.exe створено, але повний життєвий цикл поточної збірки не підтверджено: автоматична перевірка зупинилася через Access is denied до реєстру. Для встановлення/деінсталяції використовуй окремий тестовий Windows-акаунт або тестову VM без важливих даних. Якщо такого середовища немає, познач цю частину BLOCKED; Portable можна перевірити окремо.

Перевір українську/англійську мови майстра, вибір папки, ярлик у меню Пуск і вибраний ярлик робочого столу, запуск та запис у списку інстальованих програм. Інсталяція за замовчуванням має бути для поточного користувача.

У тестовому встановленні створи профіль/тестовий світ і зміни тему. Повторне встановлення тієї самої версії має зберегти ці дані. Звичайна деінсталяція має зберегти користувацькі дані. Окрему опцію очищення перевіряй лише на тестових даних; це не фізично невідновлюване стирання SSD. Якщо Windows блокує непідписану програму, запиши повідомлення; антивірус і системні дозволи змінювати для цього чекліста не потрібно.

Оновлення з 0.1.0 виконуй лише за наявності окремого тестового встановлення тієї версії. Не використовуй свої реальні світи для перевірки видалення, відновлення або конфліктів.

## 8. Що передати після перевірки

Заповни docs/HOME_TEST_RESULTS.md. Достатньо пунктів, які вдалося реально пройти. Для помилки додай: назву кроку, точні версії Minecraft/Fabric/Java, текст статусу або exit code та скріншот без секретів. Не надсилай всю portable-data чи папку secrets.

Логи Portable: portable-data/logs; логи гри: portable-data/instances/<ID профілю>/launcher-logs. В установленої версії корінь даних за замовчуванням %LOCALAPPDATA%/PTenoLauncher. Перед надсиланням переглянь конкретний лог і прибери приватні дані; не надсилай токени навіть якщо файл має назву log.

Усі ручні пункти залишаються NOT RUN, доки ти їх фактично не виконаєш. Після звіту результати можна буде внести в TEST_REPORT.md і продовжити виправлення.

Уточнення офлайн-режиму: можна додати вже наявний локальний JAR або перевірений файл із кешу. Нові файли та відсутні залежності потребують інтернету. Перевірка встановлених модів корисна перед офлайн-грою. Наступні пріоритети розробки — ліцензійний запуск, авторизація та Mod Loaders.

## Додаткова перевірка Quilt після основних сценаріїв

У новому окремому профілі PTeno-Test-Quilt вибери Minecraft 1.21.1 / Quilt, на Головній відкрий Версії Quilt, залиш релізну версію або вибери її явно й натисни Встановити / відновити. Перевір Java та готовність. Реальний запуск спочатку перевіряй без модів, лише після офіційного входу. Підтримка повних метаданих і залежностей Quilt-модів ще не реалізована; наявність встановленого Loader не підтверджує підтримку будь-якої Quilt-збірки. Не переносити важливі світи чи Fabric-моди в цей тест.
