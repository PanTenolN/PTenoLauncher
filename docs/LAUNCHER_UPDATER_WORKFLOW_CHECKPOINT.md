## Implemented workflow

- Hardened signed metadata before UI integration: exact byte signature, P-256 curve, null/missing/malformed inputs, duplicate/case-duplicate JSON fields, unknown JSON members, build/channel/schema uniqueness, file/directory/case/normalized-path collisions, protected data paths, bounded lists/archives and exact sizes/hashes. Catalog replay uses a serialized durable highest-sequence gate. Download/apply revalidates the signed offer, current inventory, staged payload and required files. Expired metadata permits validated recovery, never a new apply.
- Added a separate `PTenoLauncher.UpdateHelper` executable. Desktop copies only the baselined helper file set to an operation outside replaced paths. The helper accepts no arguments, derives its operation/data root from its location and validates its own files, signed transaction and installation binding. A ready handshake validates the exact live parent PID/start time/executable before Desktop closes. Shared application leases, the data-root mutex, profile/world/process locks and conservative active-server guards prevent unsafe replacement. PID mismatch, timeout or active components fail closed without termination.
- Portable replacement is still internal, now reachable through that verified helper. Backup/staging/journal checks remain. Interrupted apply restores the known backup instead of guessing remaining steps. Unknown/user-modified files are preserved and block unsafe recovery. A verified terminal commit with a leftover marker is safely finalized so a crash between commit and marker removal cannot strand future updates.
- New-build startup reports operation identity, exact process/build, completed settings/SQLite initialization, schema 2 and ready main window. Helper checks that proof against the process it started and rechecks signed payload files before committing. A token/process start alone is insufficient. The old version remains retained. Failed startup can roll back and restart the previous launcher. Timeout while the child is alive leaves its files/process intact and exposes recovery; neither game/server nor an application process tree is killed.
- Startup checks begin after initialization and first language selection, outside the main busy-operation path. Automatic checking and preview opt-in persist in SQLite. Offline makes zero check requests. Manual settings check, current/new sequence/version/changelog/size window, explicit Update/Later, progress/cancel and errors are wired to actual Avalonia controls. Later suppresses further offers during the session. Only Update triggers package preparation. Recovery has a distinct explanatory label and blocks other data-changing operations until resolved.
- Added a distinct Inno adapter: required signed single-process installer contract, original per-user AppId/installation/data-root ownership and registry write-access preflight without changing keys; verified uninstaller backups and owned registry snapshot; shell-free invocation with application-closing/restart/reboot disabled; process/exit/output checks; and coordinated file/uninstaller/registry recovery. Exit 3010 or any other nonzero value is not treated as success. Foreign ownership and unknown registry/uninstaller changes fail closed. There is no Portable fallback. Installer execution is not killed halfway through: its durable PID record prevents unsafe recovery while it is active.
- Added local metadata-only packaging tools, protected build sequence/ID/channel properties, managed inventory generation including the helper, channel-aware package/index preparation and external-key signing tool. The tool refuses test-trust resources and sequence-zero builds. Private keys are never embedded; the signing tool refuses a key inside the supplied source tree. `build.ps1` requires explicit valid release identity for publish. Inno configuration now uses `UseSetupLdr=no` for the supported process contract. No current Setup/Portable production artifact was created/published by this work.
- Added 36 updater texts to all eight languages: **328 matching keys** each. Existing onboarding, graphite/theme resources, optional AI, MODS-19, profiles/caches/translations/backups and account/entitlement gates are retained. Eight solution projects preserve the original layers and add helper, opt-in E2E harness and packaging utility.
