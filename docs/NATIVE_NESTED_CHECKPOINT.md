## Implemented behavior

- `LocalModManager.NativeNested.cs` reads declared Quilt `jars` and Forge/NeoForge `META-INF/jarjar/metadata.json` recursively into separate candidate metadata. It never executes mods, extracts inner JARs into mods/cache, changes original JARs or contacts AI. Outer SHA-256 covers nested bytes; each inner candidate also has its SHA-256 and source path for diagnostics. Existing Fabric inspection remains separate.
- The model keeps Maven group/artifact/artifactVersion/requested range separate from the inspected Mod ID/version. Plain FML libraries do not gain invented Mod IDs. Supported plain libraries require explicit LIBRARY/GAMELIBRARY manifest type and Automatic-Module-Name; module-info-derived/filename-derived identities remain Unknown. Root-source mod-file identity is the locator's concatenation of declared Mod IDs; NeoForge library identity has its separate library prefix. Root-source identity takes precedence without copying inner files out.
- `NativeNestedResolver` separates Quilt conditional selection from Jar-in-Jar artifact selection. It combines installed root files with pending imports. Results expose active mods, selected artifacts and explicit Unknown/unsatisfied diagnostics. Cart preview, combined local/Modrinth preview and installed-mod readiness use the result offline. Native selection is a static metadata result, not a game, security or complete compatibility verdict.
- Quilt: direct roots are mandatory in the client environment; server candidates are disabled. Nested candidates are discovered independently of whether their container is ultimately selected. `if_required`, `if_possible` and whole-ID `always` behavior are supported. Byte-identical discoveries are observationally equivalent and retain a deterministic source description. Same-ID constraints, qualified IDs, supported provides, version requirements, dependency groups, optional dependencies, dependency `unless`, conflicts and root/nested identity interactions participate in bounded weighted search.
- Quilt's preferences follow the inspected 0.30.1 OptionalModIdDefintion contract: optional ID groups permit at most one option (or exactly one when an applicable always candidate exists); per-candidate weight is 1000-index or -1000-index for if_possible. Newer supported semantic versions receive the larger index. Equal semantic versions with different bytes, equal optimum assignments and complex optional alias weights stay Unknown instead of using source enumeration order. Optional discovered valid options and all-wrong-environment dependencies follow QuiltRuleDepOnly, including exclusion of selected candidates with the wrong Maven group.
- `Core/QuiltSemanticOrder.cs` implements bounded native Quilt semantic ordering, rather than reusing Fabric predicates. It is also used by QuiltVersionConstraints and the candidate preference calculation. In the inspected source, numeric prerelease tokens match `0|[1-9][0-9]*`; leading-zero tokens therefore remain strings. Tests distinguish this from Fabric behavior. Build metadata is ignored in supported comparisons; empty suffixes and unsupported semantic forms remain Unknown. This is not a full generic-version parser.
- Populated/unsupported Quilt dependency overrides and custom `-Dloader.*` receipt properties make the profile result Unknown. A bounded, empty schema-1 overrides document is accepted. The analyzer reads configuration without rewriting it.
- Forge/NeoForge: recursively discovered descriptors are grouped by Maven identity and all supported restrictive ranges are applied. Identical eligible artifacts are reused; absent eligible embedded versions fail the supported multi-candidate case. Different eligible bytes/versions remain Unknown because inspected official selector revisions differ (older NeoForge uses unordered first match, newer Forge selects highest). The single out-of-own-range case and bare recommendations remain Unknown rather than imposing one revision's behavior on another. Selected mod metadata is checked with the existing Forge dependency/FML/features/order logic. Plain libraries remain artifacts, not mods. Duplicate module/file identity with different bytes stays Unknown.
- Missing dependencies/no supported assignment block the actual mod transaction. Preliminary combined-cart diagnostics remain dependency-related so pending remote JARs can be downloaded into cache and rechecked together before any profile change. Unknown metadata is visible in preview and prevents readiness; existing explicit Unknown Source import acknowledgement is retained. No account, Microsoft approval or Minecraft ownership check is needed for this static preparation.

## Explicit limits and unsupported cases

Per root inspection: 64 declared nested candidates total, depth four, 32 MiB per inner JAR, 128 MiB cumulative inner JAR bytes, 256 MiB expanded per inner archive / 512 MiB cumulative expanded entries, 20,000 entries per inner archive and 1 MiB metadata documents. Existing outer JAR/path/link/duplicate/zip-bomb checks remain. Limit exhaustion returns a specific Unknown; unsafe paths, archive symlinks and absent declared files are rejected without extraction. Malformed nested metadata is not fabricated into a candidate.

Profile selection: at most 128 discovered nodes; Quilt at most 18 optional candidates, 65,536 search states, 200,000 work units and two seconds. Exhaustion returns Unknown and never exposes an early partial solution as ready. Budget-related Unknown can occur earlier for complex sets. Cancellation propagates.

Unsupported: Quilt custom plugins/rules, breaks/unless SAT forms (not inferred from the RFC or Fabric), noncanonical/generic multiple-version preference ordering, multiple optional providers requiring unmodeled alias weights, populated dependency overrides/custom discovery properties, foreign/dual metadata needing another native adapter, Jar-in-Jar obfuscation, unsupported Maven ranges/recommendations, multiple eligible selector alternatives and unknown module identities. The legacy fixed-root compatibility path is retained when there are no nested candidates; this is not a universal Quilt SAT or FML discovery implementation. Extra mods directories/loader plugins/custom launch environments remain outside the confirmed default-client subset. All cross-loader bridges remain DEFERRED.

No antivirus guarantee, arbitrary plugin execution, loader emulation, classpath/gameplay verification or distribution-rights inference is made. Hashes establish integrity relative to inspected bytes, not safety or publisher identity. Original root JARs and worlds/config/settings/other profiles are preserved in isolated tests.
