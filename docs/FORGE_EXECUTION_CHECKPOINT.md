## Implemented — MINECRAFT-11 / MINECRAFT-12

- `ForgeProcessorPlan.cs` builds a separate validated execution plan. It resolves client-only data, embedded paths, declared Maven coordinates and reserved variables. Checks ordered producers, unique outputs, collisions, input overwrites, unknown substitutions, path literals/traversal/argument-file indirection, executable artifact families, supported local installertools tasks, explicit output SHA-1, manifests and declared classpaths. Implicit manifest Class-Path entries are rejected for every executable dependency. Raw metadata is never passed directly to ProcessStartInfo.
- `ForgeProcessorHost.cs` uses only a managed runtime whose complete inventory and x64/version checks pass. Runtime selection uses the verified Vanilla Java requirement. Each invocation rechecks managed runtime integrity. ProcessStartInfo.ArgumentList is used without shell; inherited environment is cleared and replaced with necessary Windows/temporary paths. No Microsoft/OpenAI credentials or inherited Java agents/options are supplied. Limits: five minutes per process, twenty-minute installation execution deadline, 10 MiB local log per processor through LiveProcessRunner; bounded lines, exit checking, cancellation and owned-tree termination. Active PID/start-time records block recovery while a previously tracked processor still runs.
- `ForgeInstaller.cs` stages verified installer, executable libraries, selected Vanilla client JAR and embedded client data under a new GUID directory `cache/forge/installations/<id>/`. The working directory is **not a sandbox for arbitrary Java code**; verified official JARs still execute with the user's ordinary permissions. No privilege elevation or system setting change is made.
- Generated outputs must uniquely map to declared Maven artifacts and have explicit SHA-1 expectations. Verify existence, size/hash, links, directory ownership and generated JAR structure before caching or commit. Inputs/prior outputs are rehashed before/after execution; modified inputs fail the operation. Unknown paths and missing/corrupt outputs cannot become a complete receipt. Tree limits: 50,000 entries / 4 GiB, generated file 256 MiB, embedded client data total 128 MiB; these are post-process disk checks, not an OS disk quota or hostile-code confinement.
- Verified outputs are retained in a hash-addressed cache. A retry stages fresh files; already verified outputs can skip their producer. An interrupted first processor / failed later processor can be retried offline if all inputs and required outputs or executable runtime are available. Unknown intermediate files are not adopted.
- Durable atomic `forge-operation.json` states: Building, Ready, Committed, Interrupted. Each operation tree also keeps `operation.json` with ProfileId/operation ownership; superseded logs/trees remain attributable. The previous installation receipt is never replaced by intermediate Vanilla preparation. Before final atomic replacement, verify every candidate file, save the previous receipt under profile `installation-backups/<id>.json`, and compare the expected previous receipt hash. Ready recovery verifies all candidate files and accepts an already committed matching candidate; a newer unrelated receipt is not overwritten. Corrupt Ready files cause a fresh rebuild. Interrupted stages/logs and old working installation files are retained; automatic cache garbage collection is not implemented.
- VanillaInstaller's internal nonpublishing preparation is used under the existing profile/world lease. Full receipt combines verified Vanilla/loader files, classpath, natives/assets, main class, JVM/game arguments, Java requirement and independent FML coordinate. Loader library-directory arguments target the canonical operation Maven tree; `${version_name}` uses the loader VersionId. Historical asset receipts remain backward compatible. Game arguments are limited to distinct modern flag/value additions.
- ReceiptValidator/readiness accept Forge/NeoForge only with the new complete generated-file/installer inventory. `ForgeInstallPlan.GameInstallationComplete` **still returns false**: a preparation plan is not a game receipt. Account, entitlement and permitted offline-session checks remain unchanged. The UI offers installation after explicit loader selection and reports unsupported formats as errors; preparation remains separate. Both hints were updated in all eight existing languages (246 keys each).

## Explicit support boundary

This is **not universal Forge/NeoForge support** and no official version has yet passed a real install in this environment. The implemented subset is spec-1 modern client profiles with explicit downloadable/embedded artifact size/SHA-1 metadata, 1–32 client processors from supported official tool families, explicit SHA-1 outputs for every processor, declared ordered Maven inputs/outputs, no implicit manifest classpath, BootstrapLauncher or ModLauncher main class, matching Vanilla Java major, and distinct flag/value game argument additions.

Legacy installers, old `net.neoforged:forge`, newer unsupported profile/checksum variants, processor chains without explicit output checksums, generated executable classpath inputs, network tasks such as DOWNLOAD_MOJMAPS, unrecognized local tasks, chained/suffixed ambiguous variables and loader Java-major overrides are rejected. A future adapter must add independently verified Mojang mapping downloads and explicitly validated contracts for installers without output metadata; do not relax checks to enable a button. FML absent/ambiguous remains Unknown. Hashes protect integrity relative to metadata, not publisher identity independently of its TLS origin or antivirus safety.

Recovery tests simulate durable journal boundaries/process cancellation. Physical power-loss, arbitrary hostile JAR containment, detached-child containment and exhaustive crash timing are not verified. Stage writes can consume disk before post-process limits run. Windows PID/start-time tracking and process-tree kill do not form a security sandbox. No automatic deletion of old operation trees or user data occurs.
