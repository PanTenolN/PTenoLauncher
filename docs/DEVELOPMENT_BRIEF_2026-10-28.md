# PTenoLauncher — продовження розробки, завершення невиконаних вимог і підготовка стабільного релізу

## 0. Головне завдання

Продовжуй розробку **PTenoLauncher** з останньої перевіреної контрольної точки.

Мені потрібна не демонстраційна програма, а повноцінний Minecraft Java Edition Launcher для Windows 11, придатний для регулярного використання.

Проєкт уже існує. Не створюй його заново.

Збережи наявну п'ятипроєктну архітектуру C# / .NET 10 / Avalonia, SQLite, усі реалізовані функції, профілі, переклади, кеші, тести та результати попередніх етапів.

**Головна вимога: реалізовувати кожну функцію до стану фактичної працездатності, а не просто наявності класу, кнопки або інтерфейсу.**

Не обмежуйся плануванням. Після аналізу поточного стану переходь до реалізації, компіляції, тестування та виправлення помилок.

# 2. Система оцінювання готовності функцій

Для кожної вимоги використовуй такі рівні:

| Готовність | Значення |
|---|---|
| 0% | Функцію не реалізовано |
| 25% | Існує архітектура або початковий код |
| 50% | Основна логіка працює, але перевірена лише частково |
| 75% | Функція реалізована й проходить автоматичні тести, але бракує важливих інтеграційних перевірок |
| 100% | Функція реалізована, пройшла необхідні автоматичні й реальні інтеграційні перевірки, документована та готова до використання |

Це контрольна шкала, а не автоматичний підрахунок за кількістю файлів чи тестів.

Поряд з оцінкою завжди показуй фактичний стан:

- VERIFIED
- PARTIALLY VERIFIED
- IMPLEMENTED BUT UNVERIFIED
- NOT IMPLEMENTED
- BLOCKED EXTERNALLY
- DEFERRED

**Ніколи не став 100% лише за успішну компіляцію або синтетичні тести.**

Якщо перевірка потребує моєї ліцензії, входу або зовнішнього дозволу, зазначай BLOCKED EXTERNALLY і працюй над іншими незалежними компонентами.

Створи й підтримуй таблицю прогресу з окремими оцінками для кожного модуля.

## P0.1. Microsoft Authentication — довести до робочого стану

Поточний стан:

- Офіційний Microsoft OAuth через браузер уже проходив.
- Код MSAL, Xbox/XSTS та Minecraft Services існує.
- Є підтримка захищеного зберігання токенів.
- Minecraft Services повертав HTTP 403.
- Я вже подав заявку на перевірку Microsoft AppID.
- Схвалення та повний успішний вхід ще не підтверджені.

Не створюй новий Microsoft-застосунок без необхідності.

Не використовуй чужі Client ID.

Не обходь перевірку ліцензії.

### Необхідно завершити

1. Коректний Xbox/XSTS authentication flow.
2. Minecraft Services authentication.
3. Перевірку Minecraft Java entitlement.
4. Отримання Minecraft Profile.
5. Нікнейм, UUID, скін.
6. Refresh Tokens.
7. Підтримку декількох акаунтів.
8. Перемикання акаунтів.
9. Вихід з акаунта.
10. Коректні повідомлення про помилки.
11. Безпечне зберігання облікових даних.
12. Перевірку стану авторизації після перезапуску лаунчера.

Для HTTP 403 реалізуй точну діагностику дозволених статусів без запису токенів, паролів, секретів або приватних відповідей.

Якщо причиною є відсутність схвалення Microsoft, не роби нескінченних повторних запитів.

Підготуй ручний сценарій тестування після отримання дозволу.

### Критерій готовності

Повна офіційна авторизація ліцензійного акаунта, отримання Minecraft Profile, оновлення токенів і повторний вхід працюють.

До цього статус не вище IMPLEMENTED BUT UNVERIFIED або BLOCKED EXTERNALLY.

## Automatic Mod Conflict Finder
