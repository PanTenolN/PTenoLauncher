# Optional dependency selection

Modrinth optional edges are shown separately with unchecked choices. Selecting a checkbox performs no network operation, invalidates the previous plan and clears both confirmations. Apply selection explicitly recalculates the combined cart. Required transitive dependencies of a selected optional component are resolved with the same deterministic compatibility rules and installed-file protections. No AI is involved.

Selections are keyed by exact parent version, project/version dependency ID and optional file metadata. Each selected edge pins its parent version, so resolution cannot silently move it onto a different parent release. Version-only dependencies resolve their published owner; file-only unidentified dependencies cannot be selected and are never converted to guessed slugs. Conflicts preserve the known choices so users can uncheck them. Removing an optional parent prunes unreachable optional descendants; components still required by another root remain. Already installed files are not removed by unchecking.

Changing local inputs, explicit catalog roots or profile clears optional selections. Editing choices or starting any recalculation discards the previous install plan. Recalculation requires a new final confirmation. Asynchronous results are rejected if profile, input cart or choice revision changed. All actual JARs still pass a final static review before the existing single installation transaction.

Limits: at most 128 requested optional keys, existing 128-root/search/archive limits and cancellation. Each parent pin/selected component counts toward the normal resolver budget. A plan that exceeds limits is blocked. Unknown/cold-cache dependencies block without network requests in offline mode. Optional components are never installed merely because an API lists them.

Evidence: OptionalDependencyTests (9 cases), LocalDependencyTests.SelectedOptionalUsesSameTransactionAndWorksFromCacheOffline and DesktopTests.OptionalCheckboxInvalidatesConfirmationAndReplansUsingCachedRealMetadataShape. The Desktop test manipulates the actual Avalonia checkbox and verifies both plan invalidation and explicit reapplication. The integration test live-optional-offline.log uses real cached Reese’s Sodium Options metadata: two optional edges, uncached selected component blocked, choice retained, clear restored the base plan, zero HTTP calls, no mod copies. It does not prove successful download or in-game behavior of a real optional component. Native UI capture ui-optional.png shows those real cached choices.

The scope is Modrinth metadata in the combined cart. Other-provider and native loader formats remain separate pending work. Full licensed Minecraft gameplay and interactive Microsoft authentication have not been executed.

Offline scope clarification: adding an existing local JAR or verified cached file does not download a new mod from the internet. Missing uncached files/dependencies require online access. Static checks of installed mods remain useful before offline gameplay. Further development priority is core licensed launch/authentication and native loader support; no additional offline-install subsystem is planned for this block.
